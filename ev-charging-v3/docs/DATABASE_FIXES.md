# Database fixes (based on the *_corrected.sql files)

I could not run MySQL myself and no error text was provided, so these fixes come from reading every file.
If an error still appears, paste the **exact error message and the file/line** and it will be fixed.

| File | Problem found | Fix |
|------|---------------|-----|
| `01_schema` | The corrected file contained `CREATE DATABASE ev_charging` + `USE ev_charging`. That silently ignores the database chosen by `scripts/install_db.sh` / `run_all_tests.sh` (they use `ev_charging_test`), so tables were built in one database and the procedures/views in another (error 1146 "table doesn't exist"), and the test script could wipe your real `ev_charging` data. | Removed. The schema file is database-agnostic again. |
| `02..05` | These files have no `USE`. Running each in a new Workbench tab gives error 1046 "No database selected". | New `00_install_all_in_one.sql` selects the database once and runs 01-04 in the right order. |
| `02_procedures` (`sp_end_session`) | The corrected energy limit (power x time **already elapsed**) rejects any normal demo or automated test: start charging, enter 12.5 kWh a few seconds later -> error 50011. Raushan's `session.test.js` (T12/T13) fails for the same reason. | Limit is now power x time from session start to the **end of the booked slot**. Still stops impossible values (51 kWh on 50 kW in 1 h is rejected). |
| `04_sample_data` | `START TRANSACTION ... COMMIT` around `CREATE PROCEDURE`/`DROP PROCEDURE`: MySQL ends the transaction at the first DDL statement, so it gave a false sense of atomicity. | Removed; header now says to run it once on a fresh schema. |
| `03_views`, `05_queries`, `tests/sql_tests` | No problem found. | Kept your corrected versions. |

## Things that can still cause errors on your computer (not visible in the files)
* MySQL older than 8.0.16: CHECK constraints are ignored or rejected. Check with `SELECT VERSION();`.
* Running `04_sample_data` twice on the same database: duplicate user emails (error 1062). Reinstall instead.
* `binlog_format=STATEMENT` with binary logging on: error 1665 when a procedure uses READ COMMITTED. Fix: `SET GLOBAL binlog_format='ROW';`.
* A SQL client that does not understand `DELIMITER` (use Workbench, the `mysql` command line, or phpMyAdmin's delimiter box).
* Workbench "Safe updates" mode blocking UPDATE/DELETE without a key (error 1175) in `sql_tests.sql`: turn it off in Preferences -> SQL Editor.
